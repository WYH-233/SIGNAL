# Input data manifest

Study data are not distributed with this code package. Before running the pipeline, obtain source data and annotations through approved/public access routes, record accession/version/licence, and create the directory structure expected by the scripts. Do not put restricted data in a public code repository.

| Input | Expected location or use | Source/accession/version |
|---|---|---|
| Control and IR2h Hi-C `.hic` files | `data/hic/ctrl/`, `data/hic/ir2h/` | To be completed |
| scATAC-seq fragments for A549_N1 and A549_C3 | `data/scatac/fragments/` | To be completed |
| Chromosome-wise observed/VC Hi-C matrices | `data/hic/{condition}/chr_observed_VC/` | Generated from `.hic` inputs |
| TAD boundaries and MD-KNN strength BED files | `data/hic/{condition}/` | Generated from Hi-C inputs; record parameter values |
| ArchR/Cicero and metacell intermediates | `data/scatac/processed/{sample}/` | Generated from scATAC-seq fragments |
| Per-chromosome graph input tables | User-selected output directory, one subdirectory per chromosome | Generated by `input_preprocessing/build_model_inputs/` or `SIGNAL.py build-inputs` |

For each data class, add dataset title, source, accession or DOI, version, file list, genome assembly, licence/access conditions and relationship to the paper. Specify which processed files are needed to reproduce each figure/table. Confirm accessions and redistribution rights with the data owner or original repository.

## Core CLI file formats

- `--metacell-matrix`: CSV with genomic peak IDs as the first/index column (`chr:start-end`) and numeric accessibility values in the remaining columns. Set `--input-dim` to the number of numeric columns.
- `--merged-loops`: tab-separated table with at least `chr1`, `start1`, `end1`, `chr2`, `start2`, `end2`, `cicero_score` and `archr_score` columns.
- `--hic-template`: chromosome-wise, tab-separated three-column contact files (`bin_start_1`, `bin_start_2`, `contact_value`) produced at the resolution given by `--binsize`. The path template must contain `{chrom_id}` or `{chrom}`.
- `--tad-strength-bed`: tab-separated, headerless four-column BED (`chromosome`, `start`, `end`, `strength`); chromosome labels must match the graph peak IDs (for example, `chr1`).
- `--input-dir` for training: graph inputs produced by `build-inputs`, with one subdirectory per chromosome and the generated accessibility z-score CSV and interaction-with-Hi-C table.

The model edge features are ordered as Cicero score, ArchR score and Hi-C observed signal; their dimension is therefore 3 for the included input builder. The input feature dimension must match the accessibility matrix column count.
